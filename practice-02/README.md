# Практическое занятие №2

## Структура Go-проекта

### Описание

### Структура проекта

```text
practice-02/
├── cmd/
│   └── myapp/
│       └── main.go
├── internal/
│   └── app/
│       ├── handlers/
│       │   └── ping.go
│       └── app.go
├── utils/
│   ├── logger.go
│   └── httpjson.go
├── go.mod
└── README.md
```

**Назначение основных директорий:**

- `cmd/myapp/` — точка входа приложения.
- `internal/app/` — основная логика HTTP-сервера.
- `internal/app/handlers/` — обработчики HTTP-запросов.
- `utils/` — вспомогательные функции логирования и формирования JSON-ответов.

### HTTP-маршруты

| Маршрут | Описание | HTTP-статус |
|---|---|---|
| `/` | Возвращает приветственный текст | 200 |
| `/ping` | Возвращает JSON со статусом и временем | 200 |
| `/fail` | Демонстрирует единый формат JSON-ошибок | 400 |

### Запуск приложения

Из директории `practice-02` выполнить:

```powershell
go run ./cmd/myapp
```

Сервер запускается на порту `8080`.

### Проверка маршрутов

```powershell
curl.exe -i http://localhost:8080/
curl.exe -i http://localhost:8080/ping
curl.exe -i http://localhost:8080/fail
```

### Дополнительные упражнения

**Упражнение A — Request-ID**

Реализован middleware `withRequestID`, который генерирует идентификатор запроса при отсутствии заголовка `X-Request-Id` и возвращает его клиенту.

Пример проверки:

```powershell
curl.exe -i -H "X-Request-Id: demo-123" http://localhost:8080/ping
```

**Упражнение B — единый формат JSON-ошибок**

Реализованы функции `WriteJSON()` и `WriteErr()`, а также маршрут `/fail`.

**Упражнение C — разделение обработчиков**

Обработчик `/ping` вынесен в отдельный пакет `internal/app/handlers`.

### Сборка и проверка

```powershell
go fmt ./...

go build -o myapp.exe ./cmd/myapp
```

### Примеры размещения артефактов

1. Исходный файл запуска приложения размещается в `cmd/myapp`, поскольку содержит точку входа.
2. Основная логика HTTP-сервера находится в `internal/app`, поскольку предназначена для внутреннего использования.
3. HTTP-обработчики размещаются в `internal/app/handlers`, чтобы отделить обработку запросов от настройки сервера.
4. Вспомогательные функции логирования находятся в `utils`, чтобы их можно было использовать в разных частях приложения.
